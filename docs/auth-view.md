# View 작업 안내: 회원가입·로그인 화면과 상단 메뉴

작성: 강준서 (View 담당) · 2026-11-13 · 브랜치 `feat/auth-view`
수정: 2026-11-14 · 브랜치 `feat/member` — 디자인을 흑백 톤으로 바꾸고 회원가입 화면 배치를 바꿨습니다.

회원가입(UC-01)과 로그인(UC-02) 화면, 그리고 모든 화면 위에 보이는 상단 메뉴를 만들었습니다. 화면은 김대원 님의 Controller 명세([docs/controller-spec.md](controller-spec.md))에 맞춰 연결되어 있습니다. 이 문서에는 화면 구조, 공통 디자인(`Theme`)과 화면 이동 규칙, 그리고 **Model 쪽에 부탁드릴 일**을 정리했습니다.

---

## 1. 바로 보기

IDE에서 `com.sadamda.App`의 `main`을 실행한 뒤, 상단 메뉴에서 **[회원가입]** 또는 **[로그인]**을 누르면 됩니다. 로그인하면 **[내 정보]**도 쓸 수 있습니다 ([docs/myinfo-view.md](myinfo-view.md)). 나머지 메뉴는 아직 "TODO" 문구만 나옵니다.

상단 메뉴는 왼쪽에 "사담다" 로고와 홈·상품·룩북, 오른쪽에 장바구니·주문 내역·로그인 관련 메뉴와 연한 회색 [글씨 크기] 버튼이 있습니다. 지금 보고 있는 화면은 굵은 글씨에 밑줄로 표시됩니다.

| 회원가입 | 로그인 |
|---|---|
| 흰 카드 맨 위에 제목과 "이미 회원이신가요? 로그인" 링크가 있고, 그 아래 필수 입력칸(비밀번호·비밀번호 확인은 한 줄에 나란히)과 "선택 입력" 묶음이 있습니다. 틀린 칸은 이름표 옆에 빨간 오류 문구가 뜨고 테두리도 빨갛게 됩니다. 맨 아래 왼쪽에 [가입취소] 링크, 오른쪽에 검정 [가입하기] 버튼이 있습니다. | 이메일·비밀번호(보기 버튼 포함), 로그인 상태 유지, 전체 폭 [로그인] 버튼, 그 아래 비밀번호 찾기·회원가입 링크가 있습니다. |

입력 폼의 사용성은 UI/UX 가이드라인(UI/UX Pro Max 스킬)의 폼·접근성 항목을 기준으로 다듬었습니다.

## 2. 바뀐 파일

| 파일 | 내용 |
|---|---|
| `view/Theme.java` (새 파일) | 모든 화면이 함께 쓰는 디자인: 색, 둥근 입력칸, 버튼, 카드 |
| `view/ScreenPanel.java` | `setContent()`, `hideTitle()` 추가 (아래 설명) |
| `view/member/SignUpPanel.java` | 회원가입 화면 |
| `view/member/LoginPanel.java` | 로그인 화면 |
| `view/MainFrame.java` | 상단 메뉴 (로그인 상태별 메뉴, 현재 화면 표시), 로그인 후 원래 화면으로 돌아가기 |

Model·Controller 코드는 **수정하지 않았습니다.** 명세에 정해진 메서드(`signUp`, `login`, `requestPasswordReset`)만 호출합니다.

## 3. 화면이 동작하는 방식

### 회원가입 (`SignUpPanel`)

| 구분 | 항목 |
|---|---|
| 필수 | 이메일, 비밀번호(8자 이상), 비밀번호 확인, 이름, 연락처 |
| 선택 | 연령대, 키(cm), 평소 사이즈, 체형 |
| 기타 | 약관 동의 체크박스 |

입력값은 화면에서 먼저 확인하고, 틀린 칸은 이름표 옆에 이유를 쓰고 테두리를 빨갛게 표시합니다 (UC-01 4b). 확인하는 때는 두 번입니다.

- **칸을 벗어날 때**: 그 칸만 바로 확인합니다. 아직 아무것도 안 쓴 빈칸은 그냥 지나가도 오류를 띄우지 않습니다.
- **[가입하기]를 누를 때**: 모든 칸을 한꺼번에 확인합니다. 틀린 곳이 있으면
  1. 맨 위에 "입력 내용을 확인해 주세요 (2곳)"처럼 개수를 알리고,
  2. 화면을 위로 올려 첫 번째 틀린 칸으로 커서를 옮깁니다. 아래쪽 버튼을 눌러도 위쪽 오류를 놓치지 않습니다.
  3. 틀린 칸을 고치면 개수가 줄고, 다 고치면 요약이 사라집니다.

| 항목 | 규칙 | 오류 문구 |
|---|---|---|
| 이메일 | 비어 있지 않고 `아이디@도메인.xx` 형식 | 이메일 형식이 맞지 않습니다 |
| 비밀번호 | 8자 이상 | 8자 이상 입력해 주세요 |
| 비밀번호 확인 | 비밀번호와 같음 | 비밀번호가 서로 다릅니다 |
| 이름 | 비어 있지 않음 | 이름을 입력해 주세요 |
| 연락처 | `010-1234-5678` 또는 `01012345678` | 010-1234-5678 형식으로 입력해 주세요 |
| 키 | 비어 있으면 통과, 입력하면 100~220 사이 숫자 (MemberService와 같은 범위) | 숫자로 입력해 주세요 |
| 약관 | 체크 필수 | 약관에 동의해 주세요 |

그 밖의 편의 기능:
- 비밀번호, 비밀번호 확인 칸 오른쪽의 **[보기]**를 누르면 입력한 글자가 보입니다. 오타를 확인할 수 있습니다.
- 비밀번호 규칙은 비밀번호 칸 아래에 "비밀번호는 8자 이상 입력해 주세요"라는 회색 안내 문구로 늘 보입니다.
- 제목 아래 **[로그인]** 링크로 바로 로그인 화면에 갈 수 있습니다.
- 오류 문구가 떠도 카드 폭이 바뀌지 않도록 입력칸 길이를 맞춰 두었습니다.
- 화면을 열면 이메일 칸에 바로 커서가 갑니다.

#### Controller 연결

검사를 통과하면 입력값을 `SignUpForm`에 담아 `context.member.signUp(form)`을 호출합니다.

| 화면 입력 | `SignUpForm` / `BodyProfile` | 비고 |
|---|---|---|
| 이메일, 비밀번호, 이름, 연락처 | `email`, `password`, `name`, `phone` | 앞뒤 공백 제거. 비밀번호 해시는 Model에서 (NFR-07) |
| 연령대, 키, 평소 사이즈, 체형 | `BodyProfile(ageGroup, heightCm, usualSize, bodyType)` | "선택 안 함"·빈칸은 `null`, 넷 다 비면 `bodyProfile` 자체가 `null` |
| 약관 동의 | `agreedToTerms` | |

| 결과 | 화면 동작 |
|---|---|
| 성공 | "가입이 완료되었습니다" 안내 → 입력칸 비우기 → 로그인된 상태로 **홈**으로 이동 (UC-01 5단계) |
| `AppException` (예: 이미 가입된 이메일, UC-01 4a) | 맨 위 빨간 글씨 자리에 메시지를 그대로 표시하고 그쪽으로 스크롤. 입력 내용은 유지 |
| `UnsupportedOperationException` (Model 미구현) | "입력 확인이 끝났습니다. 가입 처리는 아직 연결되지 않았습니다." 안내. 입력 내용 유지, 로그인 안 됨 |

> `feat/myinfo-view` 브랜치부터는 회원 Model(`feat/member-model`)이 합쳐져 있어 첫째·둘째 줄대로 동작합니다. 세 번째 줄은 Model이 없는 브랜치에서만 해당됩니다.
>
> 가입 성공 후에는 명세(UC-01)대로 **항상 홈**으로 갑니다. 로그인과 달리, 장바구니 → 로그인 → 회원가입 순서로 왔어도 장바구니로 돌아가지 않습니다.

### 로그인 (`LoginPanel`)

- **[로그인]** 또는 비밀번호 칸에서 Enter → `context.member.login(email, password)` 호출
  - **성공**: 비밀번호 칸을 비우고, `getRole()`이 관리자면 **관리자 화면**, 아니면 **로그인 전에 보던 화면**으로 돌아갑니다. 보던 화면이 없으면 홈으로 갑니다 (UC-02 4단계).
  - **`AppException`** (예: 계정 불일치, UC-02 3a): 버튼 위에 메시지를 그대로 표시합니다.
  - **Model 미구현**: "로그인 기능은 아직 연결되지 않았습니다" 안내
- **[비밀번호 찾기]** → `context.member.requestPasswordReset(email)` 호출 (UC-02 2a). 실패하면 같은 자리에 메시지를 표시합니다.
- **[회원가입]** → 회원가입 화면으로 이동
- 빈칸으로 [로그인]을 누르면 해당 칸 테두리가 빨갛게 되고 이름표 옆에 이유가 뜹니다.
- 비밀번호 칸 오른쪽 **[보기]**로 입력한 글자를 확인할 수 있고, 화면을 열면 이메일 칸에 바로 커서가 갑니다.

**`MemberService`가 구현되어 있으면 화면 코드를 고치지 않아도 회원가입과 로그인이 바로 동작합니다.** (`feat/myinfo-view`에서 확인)

| 로그인 화면에 온 경로 | 로그인 후 |
|---|---|
| 홈 → [로그인] | 홈 |
| 상품 → [로그인] | 상품 |
| 장바구니 → 로그인 → [회원가입] 들렀다 다시 로그인 | 장바구니 (회원가입을 거쳐도 처음 화면을 기억) |
| 어디서든 → 관리자 계정으로 로그인 | 관리자 화면 |

### 상단 메뉴 (`MainFrame`)

| 상태 | 오른쪽 메뉴 |
|---|---|
| 로그인 전 | 장바구니 · 주문 내역 · 로그인 · 회원가입 · [글씨 크기] |
| 일반 회원 | 장바구니 · 주문 내역 · 내 정보 · 로그아웃 · [글씨 크기] |
| 관리자 | 위 메뉴 + 관리자 |

- 왼쪽 "사담다" 로고를 누르면 홈으로 갑니다.
- 지금 보고 있는 화면의 메뉴는 굵은 글씨에 밑줄로 표시됩니다.
- [로그아웃]을 누르면 "로그아웃되었습니다" 안내 후 홈으로 갑니다.
- 메뉴는 화면을 옮길 때마다 로그인 상태를 다시 확인하므로, 로그인·로그아웃 직후 바로 바뀝니다.
- 모든 메뉴는 누르는 영역 48px 이상, 글씨는 버튼 기준(본문 +2px)이고, 키보드 포커스가 오면 테두리가 보입니다.

## 4. 공통 디자인 `Theme` 사용법

> **화면을 만드는 분(김대원 님: 관리자 화면)만 읽으시면 됩니다.** Model 담당은 건너뛰셔도 됩니다.

`Theme`은 **미리 디자인해 둔 화면 부품 모음**입니다. Swing 기본 부품은 회색 네모 모양이고, 글씨를 키우면 글자가 잘리기도 해서 둥근 입력칸, 알약 모양 버튼, 밑줄 링크, 빨간 오류 문구 등을 `Theme.java` 한 파일에 만들어 두었습니다. 화면마다 새로 만들 필요 없이 꺼내 쓰면 됩니다.

색은 **흑백 톤**입니다. 바탕은 흰색과 아주 연한 회색, 글자와 주 버튼은 거의 검정이고, **색(빨강)은 오류에만** 씁니다. 그래서 링크는 색 대신 밑줄로 구별합니다.

```java
JButton button = new JButton("저장");          // Swing 기본: 회색 네모 버튼
JButton button = Theme.primaryButton("저장");  // Theme: 검정 알약 모양 버튼, 크기·대비 기준 자동 충족
```

이렇게 쓰면 모든 화면이 같은 모양이 되고, 아래 접근성 기준도 자동으로 지켜집니다.

### 지켜지는 기준

| 기준 | 내용 |
|---|---|
| NFR-01 | 글자와 배경의 명도 대비 4.5:1 이상. 버튼 글씨는 본문보다 2px 커서, 기본 설정에서 20px |
| NFR-02 | 버튼과 링크의 누르는 영역 높이 48px 이상 |
| UC-15 | [글씨 크기]를 바꾸면 입력칸, 버튼, 체크박스, 제목이 모두 함께 커짐 |
| 키보드 사용 | Tab 키로 버튼·링크에 포커스가 오면 안쪽에 테두리가 보임 |

### 사용 예시

```java
public class MyScreen extends ScreenPanel {
    private final JTextField nameField = Theme.textField("이름 입력");   // 회색 안내 문구
    private final JLabel nameError = Theme.errorLabel();                // 빨간 오류 문구

    public MyScreen(AppContext context, MainFrame frame) {
        super(context, frame, "제목", "UC-xx");
        hideTitle();                       // 제목을 카드 안에 그릴 때
        setBackground(Theme.PAGE);

        JPanel card = Theme.card();        // 흰 카드
        Theme.addToCard(card, Theme.label("제목", 1.6f, Font.BOLD, Theme.TEXT), 0);
        Theme.addToCard(card, Theme.field("이름", nameError, nameField), 32);   // 이름표 + 입력칸
        JButton saveButton = Theme.primaryButton("저장");
        saveButton.addActionListener(e -> save());
        Theme.addToCard(card, saveButton, 32);

        setContent(Theme.centeredPage(card));   // 연한 회색 배경 가운데에 카드, 스크롤 포함
    }

    private void save() {
        boolean empty = nameField.getText().isBlank();
        nameError.setText(empty ? "이름을 입력해 주세요" : "");   // 오류 문구
        Theme.setInvalid(nameField, empty);                         // 빨간 테두리
    }
}
```

### 기능 목록

| 메서드 | 용도 |
|---|---|
| `card()` / `addToCard(card, 컴포넌트, 위쪽 간격)` | 흰 카드를 만들고, 내용을 위에서 아래로 한 줄씩 쌓음 |
| `centeredPage(card)` | 연한 회색 배경 가운데 위쪽에 카드를 놓음. 화면이 넘치면 스크롤 |
| `field(이름표, 오류라벨, 입력칸)` | "이름표 + 오류 문구"를 위에, 입력칸을 아래에 배치. 오류가 필요 없으면 `null` |
| `textField(안내문구)` / `passwordField(안내문구)` | 둥근 입력칸. 비어 있으면 회색 안내 문구, 누르면 검정 굵은 테두리 |
| `passwordWithToggle(비밀번호칸)` | 비밀번호 칸 오른쪽에 [보기]/[숨기기] 버튼을 붙인 묶음. `field(...)`의 입력칸 자리에 넣음 |
| `setInvalid(입력칸, true/false)` | 입력칸 테두리를 빨갛게 표시하거나 해제. 색만으로 알리지 않도록 `errorLabel()` 문구와 함께 씀 |
| `comboBox(항목...)` | 선택 상자 (글씨 크기에 맞춰 커짐) |
| `checkBox(문구)` | 큰 체크박스 |
| `primaryButton` / `secondaryButton` / `linkButton` | 검정 버튼 / 연한 회색 버튼 (둘 다 알약 모양) / 밑줄 있는 글자 링크 |
| `label(문구, 배율, 굵기, 색)` | 글씨 크기 조절을 따라가는 라벨. 제목은 배율 `1.6f` 정도 |
| `errorLabel()` | 빨간 오류 문구. 빈 문자열이면 보이지 않음 |
| 색 상수 | `PAGE`(아주 연한 회색 배경), `TEXT`(거의 검정), `HINT`(회색 글씨), `PRIMARY`(거의 검정), `SECONDARY`(연한 회색), `ERROR`(빨강), `LINE`(테두리) |

### 화면 이동 규칙 (`MainFrame`)

- 화면을 옮길 때는 `frame.navigate(화면클래스.NAME)`을 부릅니다. 상단 메뉴 표시도 함께 바뀝니다.
- **로그인이 필요한 화면**(장바구니, 주문, 리뷰, AI 입어보기, 내 정보, 관리자)은 Controller가 `LoginRequiredException`을 던지면 아래처럼 로그인 화면으로 보내기만 하면 됩니다. 로그인에 성공하면 자동으로 이 화면으로 돌아옵니다.

```java
try {
    List<CartItem> items = context.cart.cart();
    // ... 화면에 표시
} catch (LoginRequiredException e) {
    frame.navigate(LoginPanel.NAME);   // 로그인 후 이 화면으로 돌아옴
}
```

- 돌아온 뒤 데이터를 다시 불러오는 건 각 화면 몫입니다 (명세의 "다시 호출"). 화면이 열릴 때(`componentShown`) 불러오게 만들면 자연스럽게 처리됩니다.

### `ScreenPanel`에 추가된 메서드

- `setContent(컴포넌트)`: 화면 가운데의 "TODO" 문구를 실제 내용으로 바꿉니다. 아직 구현하지 않은 화면은 그대로 둡니다.
- `hideTitle()`: 위쪽 공통 제목을 숨깁니다. 카드 안에 제목을 직접 넣을 때 씁니다.

### 주의할 점

- 색이나 글꼴을 `setFont()`로 직접 지정하면 **[글씨 크기]를 바꿔도 따라 커지지 않습니다.** 크기가 다른 글씨가 필요하면 `Theme.label(...)`을 쓰세요.
- macOS 기본 콤보박스, 체크박스, 버튼은 글씨를 키우면 글자가 잘리거나 너무 작게 남아서 `Theme`에서 모양을 바꿔 두었습니다. 직접 `new JComboBox<>()`를 쓰지 말고 `Theme.comboBox(...)`를 쓰세요.

## 5. 담당자께 부탁드릴 일

### 백예원 님 (회원)

- **`MemberService` 구현**: `signUp`, `login`, `sendPasswordResetLink`. → `feat/member-model`로 구현해 주셨고, `feat/myinfo-view`에 합쳐 화면 수정 없이 동작하는 것을 확인했습니다.
- 실패는 명세대로 **`AppException`에 사용자에게 보여줄 문장**을 담아 주세요. 화면은 그 문장을 그대로 표시합니다.
  - 이미 가입된 이메일 (UC-01 4a) → 예: "이미 가입된 이메일입니다."
  - 계정 불일치 (UC-02 3a) → 예: "이메일 또는 비밀번호가 맞지 않습니다."
- 화면에서 넘기는 값은 3번 "Controller 연결" 표를 참고해 주세요.

### 정우진 님 (상품·추천)

- 다음 작업이 상품 목록, 상세, 홈, 룩북 화면입니다. 화면에 상품명, 가격, 이미지를 보여주려면 **`Product`, `Lookbook`의 getter**가 필요합니다 (명세 문서 3장에도 적혀 있습니다). 그 전까지는 화면 쪽 목업 데이터로 개발하겠습니다.

### 김대원 님 (Controller)

- 회원가입·로그인은 명세대로 `SignUpForm`, `AppException`, `Member.getRole()`을 써서 연결했습니다. 추가로 필요한 것은 없습니다.
- 관리자 화면도 `Theme`을 쓰시면 디자인을 맞출 수 있습니다 (4번 참고).
