# 체류시간을 늘리는 기능: 내 코디북 · 상황별 코디 도우미

담당: 정우진 · 브랜치 `feat/codi-book`

옷 입혀보기를 한 번 쓰고 끝나지 않고 다시 찾아오게 하려고 두 기능을 더했다. 메뉴는 늘리지 않았다 (NFR-03).
옷 입혀보기 화면과 홈 화면 안에 입구를 두었다.

## UC-19 내 코디북

| 항목 | 내용 |
|---|---|
| Actor | 회원 |
| 사전조건 | 로그인 상태이고, 옷 입혀보기에서 옷을 하나 이상 골랐다 (저장할 때) |
| 사후조건 | 코디(이름·그림체·신체 스펙·입힌 상품·그림)가 이 PC 에 저장되어 다시 켜도 남는다 |

**기본 흐름**
1. 회원이 옷 입혀보기에서 옷을 고른다 (입혀보기는 해도 되고 안 해도 된다).
2. 회원이 [코디북에 저장]을 누른다.
3. 시스템이 이름 입력 창을 보여준다. 기본값은 "내 코디 11월 20일" 또는 코디 도우미에서 고른 코디 이름이다.
4. 회원이 이름(예: "딸 결혼식 룩")을 넣고 확인을 누르면 시스템이 저장한다. 입혀본 그림이 지금 옷차림과 같으면 그림도 함께 저장한다.
5. 회원이 [내 코디북]을 누르면 저장한 코디가 최근 것부터 그림(없으면 첫 상품 사진)·이름·옷 수·합계·저장 시각과 함께 보인다.
6. 회원이 코디를 고르고 [다시 입혀보기](또는 두 번 누르기)를 누르면 시스템이 그림체·신체 스펙·옷·그림을 그대로 되살린다.

**대안 흐름**
- 2a. 로그인하지 않았으면 로그인한 뒤에 쓸 수 있다고 안내한다.
- 4a. 코디북에서 연 코디를 고친 뒤 저장하면 [덮어쓰기] / [새 코디로 저장] / [취소]를 묻는다. 덮어쓰면 이름은 그대로 둔다.
- 4b. 이름이 비었거나 30자를 넘거나, 고른 옷이 없으면 저장하지 않고 이유를 안내한다. 한 회원은 100개까지 모을 수 있다.
- 5a. [이름 바꾸기]로 이름을 고친다.
- 5b. [지우기]는 확인을 받은 뒤 그림 파일까지 지운다. 되돌릴 수 없다.
- 6a. 그사이 판매가 끝났거나 지워진 상품은 빼고 넣고, 뺀 개수를 알려 준다. 이때 예전 그림은 지금 옷차림과 달라서 보여주지 않는다.

**구현**: `TryOnPanel` → `CodiBookDialog` → `CodiBookController` → `CodiBookService` (`SavedCodi`)

**저장 위치**: `사용자 홈/.sadamda/codibook/{회원 열쇠}/{id}.properties` + `{id}.png`
- 회원 번호는 프로그램을 켤 때마다 다시 매겨진다. 그래서 폴더 이름에는 이메일을 쓴다. 이메일을 그대로 쓰지 않고 SHA-256 앞 16자리로 바꿔 쓴다. 파일 이름에 못 쓰는 글자를 피하고, 폴더만 보고 누구 것인지 알 수 없게 하려는 것이다.
- 상품은 id 로만 기억하고, 열 때 지금 상품 정보(가격·판매 여부)로 되살린다.

## UC-20 상황별 코디 도우미

| 항목 | 내용 |
|---|---|
| Actor | 비회원, 회원 |
| 사전조건 | 없음 |
| 사후조건 | 고른 코디가 옷 입혀보기 칸에 들어가고, AI 가 연결되어 있으면 입혀 본 그림이 나온다 |

**기본 흐름**
1. 사용자가 홈의 "어디 가세요?" 상황 버튼을 누르거나, 옷 입혀보기의 [어디 가세요? 코디 추천받기]를 누른다.
2. 시스템이 상황(결혼식·행사 / 모임·식사 / 여행·나들이 / 일상·산책)과 계절(봄·여름·가을·겨울, 처음엔 오늘 날짜의 계절)을 보여준다.
3. 사용자가 상황·계절을 고른다.
4. 시스템이 캐릭터 신체 스펙(회원이면 등록한 체형·연령대)에 맞춘 코디 3벌을 상품 사진·고른 이유·합계와 함께 보여준다.
5. 사용자가 [이 코디 입혀보기]를 누르면 시스템이 칸을 그 코디로 바꾸고 입혀 본다.
6. 사용자는 칸을 바꿔 보거나 [코디북에 저장](UC-19)으로 모아 둔다.

**대안 흐름**
- 4a. 조건에 맞는 상의나 하의가 없으면 다른 상황·계절을 골라 보라고 안내한다.
- 5a. AI 가 연결되어 있지 않으면 칸에만 넣고 [코디북에 저장]을 안내한다.

**구현**: `HomePanel` / `TryOnPanel` → `CodiHelperDialog` → `RecommendController.suggestOutfits` → `OutfitHelper`

**고르는 규칙** (`OutfitHelper`, 데이터에 상황·계절이 없어 상품 문구 낱말로 추정하는 임시 규칙)
- 상황별 자리: 결혼식·모임 = 상의·하의·주얼리·신발, 여행·일상 = 모자·상의·하의·신발
- 점수: 상황 낱말 1개당 3점(최대 6), 계절 낱말 2점, 반대 계절의 두꺼운·얇은 소재 -4점, 연령대 태그 1점, 유행 아이템 1점
- 상의·하의는 체형 태그가 맞는 것만 (맞춤 추천 UC-08 과 같은 규칙)
- 자리마다 점수순으로 줄 세워 1·2·3번째를 묶는다. 그래서 세 코디의 상품이 서로 다르고, 같은 조건이면 늘 같은 결과가 나온다.
