# View 작업 안내: 내 정보 화면

작성: 강준서 (View 담당) · 2026-11-14 · 브랜치 `feat/myinfo-view`

내 정보(UC-03 회원·체형 정보 관리) 화면을 만들었습니다. 회원이 연락처, 기본 배송지, 연령대, 체형 정보를 보고 고칠 수 있습니다. 화면은 Controller 명세([docs/controller-spec.md](controller-spec.md))의 `myInfo()`, `updateProfile(...)`에 연결되어 있고, 회원 Model(`feat/member-model`)을 이 브랜치에 merge해서 실제로 저장까지 동작합니다.

공통 디자인(`Theme`)과 화면 이동 규칙은 [docs/auth-view.md](auth-view.md)를 참고해 주세요.

---

## 1. 바로 보기

1. IDE에서 `com.sadamda.App`의 `main`을 실행합니다.
2. 상단 메뉴 **[회원가입]**으로 가입합니다. 가입하면 바로 로그인됩니다.
3. 상단 메뉴 **[내 정보]**를 누릅니다. 이 메뉴는 로그인했을 때만 보입니다.

> 지금 `MemberService`는 회원 정보를 메모리에만 저장합니다. 앱을 다시 켜면 가입부터 다시 해야 합니다.

화면 구성 (위에서 아래로):

| 영역 | 내용 |
|---|---|
| 맨 위 | 회원 이름("홍길동 님")을 크게, 그 아래 이메일을 회색으로. **보기 전용**이라 고칠 수 없습니다 |
| 연락처와 배송지 | 연락처, 기본 배송지 |
| 체형 정보 | 연령대, 키(cm), 평소 사이즈, 체형. "저장하면 추천 옷에 바로 반영돼요" 안내 |
| 버튼 | **[저장하기]**(검정), **[되돌리기]**(연한 회색) |

## 3. 화면이 동작하는 방식

### 화면을 열 때 (UC-03 1~2단계)

- 화면이 열릴 때마다 `context.member.myInfo()`로 저장된 정보를 다시 불러와 칸을 채웁니다. 다른 화면에서 정보가 바뀌어도 항상 최신 값이 보입니다.
- 저장된 값이 없는 항목은 빈칸 또는 "선택 안 함"으로 보입니다. 선택지에 없는 값이 저장되어 있어도 "선택 안 함"으로 보입니다.
- 로그인하지 않은 상태라 `LoginRequiredException`이 오면 로그인 화면으로 보냅니다. 로그인하면 이 화면으로 돌아옵니다.

### 입력 검사 (UC-03 4a)

회원가입과 같은 방식입니다. 칸을 벗어날 때 그 칸을 확인하고, [저장하기]를 누르면 전체를 확인합니다. 틀린 칸은 이름표 옆에 이유를 쓰고 테두리를 빨갛게 표시합니다. 맨 위에는 "입력 내용을 확인해 주세요 (2곳)"처럼 개수를 알리고, 첫 번째 틀린 칸으로 커서를 옮깁니다.

| 항목 | 규칙 | 오류 문구 |
|---|---|---|
| 연락처 | 필수. `010-1234-5678` 또는 `01012345678` | 연락처를 입력해 주세요 / 010-1234-5678 형식으로 입력해 주세요 |
| 기본 배송지 | 자유 입력, 비워도 됨 | 없음 |
| 키 | 비어 있으면 통과. 입력하면 100~220 사이 숫자 | 숫자로 입력해 주세요 / 100~220 사이로 입력해 주세요 |
| 연령대, 평소 사이즈, 체형 | 선택 상자. "선택 안 함" 가능 | 없음 |

선택지는 회원가입 화면과 같습니다 (auth-view.md 6번 참고).

### Controller 연결 (UC-03 3~4단계)

검사를 통과하면 `context.member.updateProfile(phone, defaultAddress, bodyProfile)`을 호출합니다.

| 화면 입력 | 넘기는 값 | 비고 |
|---|---|---|
| 연락처 | `phone` | 앞뒤 공백 제거 |
| 기본 배송지 | `defaultAddress` | 앞뒤 공백 제거. 비우면 빈 문자열 (Model이 `null`로 저장) |
| 연령대, 키, 평소 사이즈, 체형 | `BodyProfile(ageGroup, heightCm, usualSize, bodyType)` | "선택 안 함"·빈칸은 `null`. 넷 다 비면 `bodyProfile` 자체가 `null` |

| 결과 | 화면 동작 |
|---|---|
| 성공 | "내 정보를 저장했습니다." 팝업 → 저장된 값으로 칸을 다시 채움 (Model이 정리한 연락처 `010-9876-5432` 형태가 보임) |
| `AppException` (형식 오류 등) | 맨 위 빨간 글씨 자리에 메시지를 그대로 표시. 입력 내용 유지 |
| `LoginRequiredException` | 로그인 화면으로 이동 |

### [되돌리기]

저장하지 않고 바꾼 내용을 버리고, 저장된 값과 오류 없는 상태로 되돌립니다. 다른 화면으로 이동하지는 않습니다.

> 저장하지 않고 상단 메뉴로 다른 화면에 가면, 바꾼 내용은 안내 없이 사라집니다. 다시 들어오면 저장된 값이 보입니다.

## 4. 회원가입 화면에서 함께 바뀐 것

두 화면이 같은 규칙을 쓰도록 맞췄습니다.

| 항목 | 이전 | 지금 | 이유 |
|---|---|---|---|
| 키 범위 | 100~250 | **100~220** | `MemberService`가 100~220만 받음. 화면이 더 넓게 받으면 화면 검사는 통과하고 저장에서 실패함 |
| 연락처 오류 문구 | 연락처 형식이 맞지 않습니다 | **010-1234-5678 형식으로 입력해 주세요** | 무엇이 틀렸는지뿐 아니라 어떻게 고치는지 알려 주도록 |

선택지(`AGE_GROUPS`, `SIZES`, `BODY_TYPES`)와 검사 함수(`phoneMessage`, `heightMessage` 등)는 `SignUpPanel`에 하나만 두고 `MyInfoPanel`이 가져다 씁니다. **선택지나 검사 규칙을 바꿀 때는 `SignUpPanel` 한 곳만 고치면 두 화면에 모두 적용됩니다.**

## 5. 담당자께 부탁드릴 일

### 백예원 님 (회원)

- `MemberService.updateProfile`, `findById`를 써서 화면 수정 없이 저장까지 동작하는 것을 확인했습니다. 감사합니다.
- 키 범위(100~220)나 연락처 형식을 Model에서 바꾸시면 알려 주세요. 화면 검사도 같이 맞추겠습니다.

### 정우진 님 (추천)

- 맞춤 추천(UC-08)에서 체형 정보를 쓰실 때, `BodyProfile`에는 **화면 선택지 문자열이 그대로** 들어갑니다. 예: `ageGroup="50대"`, `usualSize="M (66)"`, `bodyType="보통 체형"`. 다른 값(코드값 등)이 필요하면 말씀해 주세요.
