# View 작업 정리: 화면 디자인·시트 데이터·상품 상세·상품 화면과 카드·홈 화면·로고

작성: 강준서 (View 담당) · 2026-11-17 ~ 2026-11-22 · 브랜치 `feat/order-view` → `feat/ui-redesign`
(11-22에 따로 적었던 `ui-design-update.md`는 이 문서로 합쳤습니다)

UC7~9 브랜치(`feat/product-recommend-model-compat`)를 합친 뒤, 화면 모양을 하나로 맞추고 구글 시트의 상품 370개를 앱 데이터로 넣었습니다(11-17). 상품 목록·상세 화면은 이제 **목업이 아니라 실제 데이터(`ProductService`)로 동작**합니다. 이어서 11-22에 홈 화면을 **진보라 띠 + 넓은 검색창 + 카테고리 탭**으로 새로 디자인하고, 상품 화면(알약 필터·글자 카테고리 탭), 상품 카드(찜 하트·찜 수·별점), 상단 메뉴 글씨 고정, 새 로고를 더했습니다. 홈·룩북·옷 입혀보기는 흰 바탕으로 바꿨고, 상단 메뉴에 테두리가 저절로 생기던 문제와 장바구니에서 버튼이 잘리던 문제도 고쳤습니다.

> **정우진 님**: 담당 파일을 여러 개 고쳤습니다. 합치기 전에 [10. 다른 담당 파일 변경](#10-다른-담당-파일-변경)과 [11. 팀과 상의할 점](#11-팀과-상의할-점)을 꼭 봐 주세요.

## 2. 화면 디자인 통일과 흰 바탕

### 2.1 `Theme` 디자인으로 통일 (11-17)

홈·룩북·옷 입혀보기를 상품·주문 화면과 같은 `Theme` 디자인으로 맞췄습니다.

- **`ShopUi`**: 색·글씨·버튼을 모두 `Theme`에서 가져옵니다. 따로 그리던 버튼(RoundButton)은 없앴습니다.
- **홈·룩북**: 검색창과 선택 상자는 `Theme` 입력칸, 룩북 제목은 상품 화면과 같은 크기, [← 코디 목록으로]는 밑줄 링크입니다.
- **옷 입혀보기**: 제목과 구분선, 그림체 칩(2×2), `Theme` 버튼, 흰 카드 모양의 옷 칸을 씁니다. 상품 고르기·보관함·스펙·AI 설정 창도 같은 입력칸과 버튼을 씁니다.
- **`Theme` 비활성 버튼**: 누를 수 없는 버튼은 흰 바탕·테두리·회색 글씨로 그립니다(품절 칩과 같은 모양). **앱 전체에 적용**됩니다.

### 2.2 바탕색을 흰색으로 (11-22)

공통 색 `Theme.PAGE`(연한 회색 `#F2F2F2`)는 **그대로 두고**, 아래 화면에서만 흰색(`CARD`)을 씁니다. 장바구니·주문 내역 등 다른 화면은 여전히 회색입니다.

| 화면 | 파일 |
|---|---|
| 홈 | `HomePanel` |
| 룩북 (목록·코디 보기) | `LookbookPanel` |
| 옷 입혀보기 | `TryOnPanel` |

룩북 화면에서는 [새 코디 올리기] 버튼도 없앴습니다. 새 코디는 **관리자 화면 → 룩북 탭의 [새 코디 등록]** 에서 올립니다. 코디 보기의 관리자용 [수정]·[삭제]는 그대로입니다.

## 3. 홈 화면 (`HomePanel`, `CategoryBar`)

### 3.1 맨 위 진보라 띠

- 예전의 인사말 카드와 "카테고리로 찾기" 섹션을 없애고, **창 폭 가득한 진보라 띠**(`#6A4BD8`) 하나로 합쳤습니다.
- 띠 안에는 **흰 사각 검색창**과 그 아래 **카테고리 탭**만 있습니다. 인사말("어서 오세요, 사담다입니다." 등)은 뺐습니다.
- 검색창은 오른쪽 돋보기 버튼을 누르거나 Enter로 검색합니다(UC-05). 포커스가 있으면 진한 테두리가 생깁니다.
- 띠를 창 끝까지 붙이려고 `HomePanel`의 바깥 여백(`ScreenPanel`의 24px)을 없앴습니다. 띠 아래 섹션들은 따로 좌우 32px 여백을 둡니다.
- 글자 대비: 띠 위 흰 글씨 5.8:1, 연보라 글씨(`#EEEAFF`) 4.9:1 (NFR-01 4.5:1 이상).
- **고정 줄**: 화면을 내려 띠가 위로 사라지면, 맨 위에 같은 진보라 카테고리 탭 줄이 고정됩니다. 내용 위에 겹쳐 그려서 목록이 밀리지 않습니다(`withPinnedCategories`). 11-17에는 회색 카테고리 버튼 줄이었고 새 디자인에서 이렇게 바뀌었습니다.

### 3.2 카테고리 탭 (`CategoryBar`)

- 회색 알약 버튼 대신 **글자만 있는 탭**입니다. 상품 화면의 탭과 같은 크기(20px)·간격이고, 글자는 항상 굵게 씁니다.
- 맨 앞에 [전체] 탭이 있어서 예전의 [전체 상품 보기] 버튼을 대신합니다.
- 상품 수 숫자("상의 35")는 글자에서 빼고 툴팁·스크린리더 이름으로만 알립니다.
- 탭 색을 바꾸는 `setColors(평소 글씨, 고른 글씨, 밑줄)`을 추가했습니다. 홈에서는 연보라 → 흰 글씨·흰 밑줄을 씁니다. 지정하지 않으면 흰 바탕용 기본색(회색 → 검정)입니다.
- 홈으로 돌아왔을 때 탭이 눌린 채로 남지 않게 `clearSelection()`을 추가했습니다.
- `CategoryBar`는 홈에서만 쓰므로 다른 화면에는 영향이 없습니다.

### 3.3 섹션 정리

모든 섹션의 오른쪽 회색 버튼을 없애고, 필요한 것만 **안내 문구 바로 아래 밑줄 글자 링크**로 바꿨습니다. 마우스로 눌러도 링크에 테두리가 생기지 않습니다(Tab 키로 오면 보임).

| 섹션 | 바뀐 점 |
|---|---|
| 나에게 어울리는 상품 (비회원) | 안내 문구 삭제, [로그인하기] → 링크 |
| 나에게 어울리는 상품 (체형 정보 없음, 3a) | [체형 정보 입력하기] → 링크 |
| 이번 시즌 유행 아이템 | 안내 문구 삭제, [유행 아이템 모두 보기 (N개)] ↔ [줄여 보기] → 링크 |
| 추천 코디 | [코디 모두 보기] 삭제 (상단 메뉴 [룩북]으로 이동 가능) |
| 옷 입혀보기 | [옷 입혀보기] → 링크 |
| 새로 들어온 상품 | [상품 더 보기] 삭제 (띠의 [전체] 탭·상단 메뉴 [상품]으로 이동 가능) |

### 3.4 맨 위로 올라가기

홈에서 상단 "사담다" 로고를 누르면 맨 위로 올라갑니다(`HomePanel.scrollToTop()`). 홈 상품 카드의 글씨 모양과 찜 하트는 5장입니다.

## 4. 상품 화면 (UC-04·05, `ProductListPanel`)

[상품] 화면의 모양을 바꿨습니다. 동작은 예전과 같고, 필터를 훨씬 쓰기 쉽게 했습니다.

### 4.1 카테고리 탭과 따라오기

- **글자 탭**: 둥근 버튼 대신 글자만 있는 탭입니다(고른 탭은 굵은 글씨와 검은 밑줄). 큰 "상품" 제목은 없앴습니다. 탭 글씨는 [글씨 크기]와 상관없이 **"보통"(20px)으로 고정**합니다(`CategoryTab`, 8.1 참고).
- **탭 따라오기**: 예전에는 검색창과 카테고리 탭이 한 덩어리로 위에 고정되어 있었습니다. 이제 목록을 내리면 **검색창은 함께 올라가 사라지고, 카테고리 탭이 맨 위에 닿으면 붙어서 따라옵니다.**
- 방법: 머리말을 목록 위에 겹쳐 두고, 스크롤한 만큼 위로 밀어 올리다가 탭이 맨 위에 닿으면 멈춥니다(`withStickyTabs`). 탭을 따로 하나 더 만들지 않습니다. 목록 맨 위에는 머리말 높이만큼 여백을 둡니다(`Body.setTopSpace`). 카테고리를 바꾸면 목록이 맨 위로 가서 검색창이 다시 보입니다.

### 4.2 필터가 늘 보임

예전에는 검색한 뒤에만 보였습니다. 이제 카테고리를 볼 때도 보이고, 고르면 **[적용] 없이 바로** 목록이 바뀝니다.

- 알약 모양 버튼 5개: `[연령대 ∨] [체형 ∨] [사이즈 ∨] [가격대 ∨] [색상 ∨]` (`FilterPill`). 누르면 선택지 목록이 열리고, 고르면 버튼 글자가 고른 값(예: "50만원 이상")으로 바뀌며 검정 바탕이 됩니다. 첫 선택지는 "전체"(조건 없음)입니다.
- 그 아래 왼쪽: `☐ 내 체형에 맞는 상품`(체형 정보가 있는 회원에게만, 체크하면 연령대·체형·사이즈를 내 정보로 채움, 직접 바꾸면 체크가 풀림)과 [필터 초기화].
- 오른쪽: `인기순 ↑↓`. 누르면 인기순·신상품순·낮은 가격순·높은 가격순 목록이 열립니다. 예전의 정렬 칩 4개를 하나로 합쳤습니다.

### 4.3 카테고리 화면에도 필터

`SearchFilter`에 카테고리 조건이 없어서, 조건으로 검색한 결과 중 그 카테고리 상품만 **화면에서 골라** 보여 줍니다(Model·Controller는 바꾸지 않았습니다). [더 보기]는 그 결과를 `ProductService.PAGE_SIZE`(8)개씩 덧붙입니다.

- 카테고리 탭을 바꾸면 고른 필터는 그대로 유지합니다.
- 새로 검색하면 필터와 정렬은 처음 상태로 돌아갑니다.
- 필터 때문에 결과가 없으면 "조건에 맞는 상품이 없어요"와 [필터 초기화] 안내가 나옵니다.

### 4.4 인기순 기준 (`ProductService`)

많이 팔린 순 → 유행 아이템 → 등록 순입니다. 데모 데이터에는 판매 수가 없어서 처음에는 사실상 유행 → 등록 순입니다. 주문하면 그 상품이 올라가지만 앱을 끄면 다시 0이 됩니다.

### 4.5 검색 수정 (11-17)

| 문제 | 원인 | 고친 내용 |
|---|---|---|
| 홈에서 검색해도 상의 목록만 나옴 | `ProductListPanel`에 홈이 부르는 `openSearch`·`openCategory`가 없었음 | 두 메서드 추가 |
| 검색하면 오류(`NullPointerException`) | 병합으로 카테고리가 8개가 됐는데 목업 데이터는 4개뿐 | 목업을 실제 데이터로 바꾸면서 해결(7장) |

## 5. 상품 카드 (상품 화면 `ProductCard`, 홈 `ShopProductCard`)

두 카드의 글씨와 찜 기능을 같은 모양으로 맞췄습니다.

- **글씨 모양**: 브랜드(굵게, 뒤에 가는 `>`) → 상품명(보통 굵기, 두 줄까지) → 가격(크고 굵게). `>`는 공용 `ChevronIcon`입니다. 상품 데이터에 할인율이 없어서 할인 표시는 없습니다.
- **찜 하트**: 누르면 상세로 가지 않고 **바로 찜/해제**합니다. 찜하지 않았으면 흰 테두리, 찜했으면 빨간 하트입니다. 누르는 칸은 48px입니다(NFR-02).
  - 상품 화면 카드: 사진 오른쪽 아래.
  - 홈 카드: 카드 맨 아래 오른쪽(칩과 같은 줄).
  - 비회원이 누르면 로그인 화면으로 가고(로그인하면 돌아옴), 찜하면 아래에 "찜했어요 [찜 목록 보기]" 안내가 뜹니다.
- **상품 화면 카드의 `♥ 찜 수   ★ 별 평균 (별 준 사람 수)` 줄**(회색 작은 글씨). 별점은 리뷰를 쓸 때만 줄 수 있어서 별 준 사람 수는 리뷰 수와 같습니다. 별 평균은 소수 한 자리이고 딱 떨어지면 "5"처럼 표시합니다(상품 상세는 "5.0"). 3,000이 넘으면 "3.1천", 1만이 넘으면 "1.2만"으로 줄입니다. 리뷰가 없으면 `★ 0 (0)`입니다.
- **홈 카드의 칩**: [유행]·[품절]·분류 칩을 카드 **맨 아래 왼쪽**에 둡니다. 같은 줄의 카드는 높이가 같아서 상품명이 몇 줄이든 칩과 하트가 가지런합니다. 홈 카드에는 찜 수·별점 줄이 없습니다.
- **공용 부품**: `HeartButton`(하트 모양), `WishActions`(찜하기·로그인 안내·"찜했어요" 안내·리뷰 가져오기), `ChevronIcon`. `ProductItem`에 `brand`를 더했고, 찜 수는 `CartService.countWishes` → `CartController.wishCount`로 셉니다.
- 데모 데이터에서는 찜이 거의 없고 리뷰도 거의 없어서 대부분 `♥ 0   ★ 0 (0)`으로 보입니다.

## 8. 상단 메뉴와 로고 (`MainFrame`, `SadamdaLogo`)

### 8.1 글씨 크기 고정

상단 메뉴 줄(로고·메뉴·[글씨 크기]) 글씨는 [글씨 크기]와 상관없이 "보통" 기준으로 고정합니다(`MainFrame.MENU_FONT_SIZE`는 `FontSize.NORMAL.px()`). 글씨를 키워도 메뉴가 한 줄에 들어가게 하려는 것입니다. 이를 위해 `FontSize.px()`와 `Theme.secondaryButton(문구, 기준 크기)`를 추가했습니다(기존 버튼은 그대로). 상품 화면의 카테고리 탭도 같은 이유로 고정했습니다(4.1).

### 8.2 새 로고 `SadamdaLogo`

40~50대 고객에게 맞게 차분하고 단정한 **명조 글자**입니다. 컴퓨터에 설치된 명조 글꼴(나눔명조 → 애플명조 → 바탕 → …)을 찾아 쓰고, 없으면 앱 기본 굵은 글씨로 대신합니다. 글꼴 파일은 저장소에 넣지 않았으므로 **컴퓨터마다 글자 모양이 조금 다를 수 있습니다.** 굵기·글자 사이 간격은 파일 위쪽의 상수(`WEIGHT`, `SPACING`)로 바꿉니다. 로고를 누르면 홈으로 가고, 이미 홈이면 맨 위로 올라갑니다(3.4).

### 8.3 메뉴에 네모 테두리가 저절로 생김 (11-22 수정)

- **증상**: 로그인 후나 화면을 옮긴 뒤 [홈] 메뉴나 사담다 로고에 네모 테두리가 남아 있었습니다.
- **원인**: 화면이 바뀌어 포커스가 있던 칸(예: 로그인 화면의 비밀번호 칸)이 사라지면, Java가 포커스를 창 맨 앞 버튼(로고·[홈])으로 저절로 옮깁니다. 테두리는 포커스가 있을 때 그려지므로 클릭하지 않아도 생겼습니다.
- **수정**: 상단 메뉴줄의 모든 버튼(로고, 메뉴, [글씨 크기])이 **포커스를 받지 않게** 했습니다(`setFocusable(false)`). 메뉴의 포커스 테두리를 그리던 코드도 지웠습니다. 마우스 동작은 그대로입니다.

## 11. 팀과 상의할 점

1. **흑백 테마 규칙의 예외**: `Theme` 주석에는 "흑백 톤, 색은 오류(빨강)에만 쓴다"고 되어 있습니다. 홈 화면 띠에만 진보라(`#6A4BD8`)를 썼습니다. 다른 화면에도 쓸지, 홈에서만 쓸지 정해야 합니다. 색은 `HomePanel`의 `BAND` 상수 하나로 바꿀 수 있습니다.
2. **글씨 크기 고정과 NFR-01**: 상단 메뉴·로고·상품 카테고리 탭은 [글씨 크기]와 상관없이 "보통"으로 고정했습니다(8.1, 4.1). 글씨를 키워 쓰는 분에게는 이 부분이 커지지 않으므로 NFR-01(글씨 크기 조절)과 어긋나지 않는지 정해야 합니다.
3. **상단 메뉴 키보드 사용**: 8.3의 수정으로 Tab 키로는 상단 메뉴에 갈 수 없습니다. 키보드만으로 메뉴를 쓸 수 있어야 한다는 요구사항이 있으면 다른 방법(예: 단축키)이 필요합니다.
4. **홈에서 다른 화면으로 가는 길**: [코디 모두 보기]·[상품 더 보기]를 없앴으므로, 룩북·전체 상품은 상단 메뉴나 띠의 [전체] 탭으로 갑니다.
5. **맥과 윈도우의 글꼴 차이**: 앱이 글꼴을 정하지 않고 컴퓨터 기본 글꼴을 쓰기 때문에, 상품 이름 같은 글자가 맥(애플 글꼴)과 윈도우(맑은 고딕 계열)에서 다르게 보입니다. 로고의 명조 글꼴도 컴퓨터마다 다릅니다. 앱에 글꼴 파일(예: 나눔고딕, 약 4MB)을 함께 넣으면 모든 컴퓨터에서 같아지지만, 맥 화면도 달라지고 저장소가 커집니다(12장).

## 12. 시도했다가 되돌린 것

최종 코드에는 없습니다. 같은 시도를 반복하지 않도록 적어 둡니다.

- 홈 검색 카드의 파스텔 그라데이션·반짝이 장식 → 진보라 띠로 바뀜

- 홈 띠의 "사담다" 글자 → 삭제
- 사담다 로고를 두꺼운 고딕으로 변경 → 명조로 되돌림. (그 전에 만든 굵은 기울임 글자 + 끝점 로고도 명조로 바뀌었습니다.)
- 룩북 화면 위쪽에 진보라 띠 → 원래대로 되돌림 (흰 바탕만 유지)
- 앱 전체 글꼴을 나눔고딕으로 통일(글꼴 파일을 앱에 넣음) → 맥 화면이 달라져 되돌림. 윈도우에서 글꼴이 다르게 보이는 문제는 그대로입니다(11장 5번).

## 13. 확인한 것과 못 한 것

- **컴파일**: 전체 소스를 `javac --release 17`과 `mvn compile`로 컴파일해 오류가 없음을 확인했습니다.
- **화면 모양**: 홈 띠, 상세 화면의 수량 줄·색상 칩, 상품 화면의 필터 목록(누르면 열리는 선택지), 로그인한 회원의 `☐ 내 체형에 맞는 상품`은 실제 앱에서 직접 눌러 보지 못한 부분이 있습니다. 기능은 창 없이 실행해서 확인했습니다. 특히 **상품 화면 스크롤(4.1)** 과 **로그인 후 메뉴 테두리(8.3)** 는 각자 앱에서 봐 주세요. 글씨 크기 "아주 크게"일 때 화면도 일부만 보았습니다.
- **하트 모양**: 실제 상품 사진 위에서 흰 하트가 잘 보이는지는 앱에서 봐야 합니다(그림으로는 사진을 내려받기 전의 회색 칸 위에서만 확인).
- **AI 입혀보기**: AI가 연결된 상태에서 [입혀보기]를 눌러 실제로 입혀지는지는 이용 열쇠가 없어 확인하지 못했습니다.
- **로고 글꼴**: 나눔명조가 설치된 컴퓨터에서만 확인했습니다. 명조 글꼴이 없는 컴퓨터(예: 윈도우)에서는 기본 굵은 글씨로 보입니다.
- **테스트**: `mvn test`에서 52개 중 51개가 Mockito 오류(`Could not modify all classes`)로 실행되지 않습니다. 이번 변경 전 커밋에서도 똑같이 실패하므로 환경 문제로 보입니다.
