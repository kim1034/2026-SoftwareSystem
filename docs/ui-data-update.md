# View 작업 정리: 화면 통일·시트 데이터 적용·상품 상세 개선

작성: 강준서 (View 담당) · 2026-11-17 · 브랜치 `feat/order-view`

UC7~9 브랜치(`feat/product-recommend-model-compat`)를 합친 뒤, 화면 모양을 하나로 맞추고 구글 시트의 상품 370개를 앱 데이터로 넣었습니다. 상품 목록·상세 화면은 이제 **목업이 아니라 실제 데이터(`ProductService`)로 동작**합니다. 상품 상세에는 수량 선택, 색상 칩 색 표시, AI 입어보기 연결을 더했습니다.

> **정우진 님**: 담당 파일을 여러 개 고쳤습니다. 합치기 전에 [7. 다른 담당 파일 변경](#7-다른-담당-파일-변경)을 꼭 봐 주세요.

---

## 1. 바로 보기

1. IDE에서 `com.sadamda.App`의 `main`을 실행합니다.
2. 아래 순서로 눌러 보면 이번 변경을 대부분 볼 수 있습니다.

| 해 볼 것 | 보이는 결과 |
|---|---|
| 홈 검색창에 "캐시미어" 입력 → [검색] | 상품 목록에 "'캐시미어' 검색 결과 44개" |
| 홈을 아래로 내리기 | 맨 위에 카테고리 버튼 줄이 고정되어 나타남 |
| 홈에서 상단 "사담다" 로고 누르기 | 홈 맨 위로 올라감 |
| [상품] → [가방] | 가방 5개 |
| 상품 카드 → 색상 칩 고르기 | 칩이 그 색(베이지, 네이비 등)으로 채워짐 |
| 상세에서 [+] 누르기 | "3개 · 합계 2,220,000원"처럼 바뀜, 재고(10개)에서 멈춤 |
| 바지 상세에서 [AI로 입어보기] (로그인 필요) | 옷 입혀보기 화면의 하의 칸에 그 바지가 들어감 |

## 2. 화면 디자인 통일

홈·룩북·옷 입혀보기를 상품·주문 화면과 같은 `Theme` 디자인으로 맞췄습니다.

- **`ShopUi`**: 색·글씨·버튼을 모두 `Theme`에서 가져옵니다. 따로 그리던 버튼(RoundButton)은 없앴습니다.
- **홈·룩북**: 검색창과 선택 상자는 `Theme` 입력칸, 룩북 제목은 상품 화면과 같은 크기, [← 코디 목록으로]는 밑줄 링크입니다.
- **옷 입혀보기**: 제목과 구분선, 그림체 칩(2×2), `Theme` 버튼, 흰 카드 모양의 옷 칸을 씁니다. 상품 고르기·보관함·스펙·AI 설정 창도 같은 입력칸과 버튼을 씁니다.
- **`Theme` 비활성 버튼**: 누를 수 없는 버튼은 흰 바탕·테두리·회색 글씨로 그립니다(품절 칩과 같은 모양). **앱 전체에 적용**됩니다.

## 4. 시트 데이터 적용 (상품 370개)

[구글 시트](https://docs.google.com/spreadsheets/d/1OEbyJTQ3_8mpnIesrYRcQPwiPQlF9hbfUxq6GUTmyi4/edit?gid=0#gid=0)로 `src/main/resources/data/products.tsv`를 다시 만들었습니다. 기존 300개는 시트와 똑같아서 그대로이고, **70개가 추가**됐습니다.

| 상의 | 하의 | 원피스 | 아우터 | 모자 | 신발 | 양말 | 주얼리 | 가방 | 스카프 |
|---|---|---|---|---|---|---|---|---|---|
| 35 | 35 | 5 | 5 | 35 | 105 | 35 | 105 | 5 | 5 |

- **`Category`**: 가방(`BAG`)·스카프(`SCARF`)를 추가했습니다. 두 카테고리의 사이즈 옵션은 `FREE` 하나입니다.
- **상품 목록·상세**: `ProductListPanel`·`ProductDetailPanel`의 fetch 메서드가 `context.product`를 씁니다. 예전에 모델 담당에게 부탁하려던 "fetch 메서드 5개 교체"는 끝났습니다.
- **`MockProducts`**: 가짜 상품 20개를 지웠습니다. 이때는 장바구니·주문·리뷰 목업이 같은 상품 데이터를 보도록 연결하는 통로만 남겨 두었고, 11-19 통합(`feat/integrate-real-models`, [docs/integration.md](integration.md))에서 목업과 함께 `MockProducts`도 지웠습니다. 지금 `MainFrame`은 `MockProducts.connect`를 부르지 않습니다.
- **데모 주문·리뷰**: 상품 번호 대신 상품 코드(`TOP-KR-02` 등)로 상품을 찾게 했습니다. 통합 뒤 데모 리뷰는 없어졌고, 시연용 예전 주문은 `controller/DemoData`가 같은 방식(상품 코드)으로 실제 `OrderService`에 넣습니다.
- **변환 메서드**: `ProductItem.of(Product)`, `ProductDetail.of(Product)`를 추가했습니다.

> 시트 데이터는 모든 옵션의 재고가 10개입니다. 그래서 상세 화면의 품절 칩(UC-06 4b)은 지금 볼 수 없습니다.

## 5. 상품 상세 화면 (UC-06)

| 항목 | 내용 |
|---|---|
| 사이즈·색상 칩 | 고르지 않은 칩은 흰 바탕에 테두리, 고른 칩은 검정 |
| 색상 칩 색 | 고르면 그 색으로 채움. 이름에서 가장 앞의 색 낱말로 색을 정함("차콜 블랙" → 차콜). 모르는 이름("기본", "레오파드")은 검정. 화이트처럼 밝은 색은 진한 테두리로 고른 것을 표시 |
| 구매 수량 | 색상 아래 `[−] N개 [+]   합계 ○○원`. 1개 미만으로 줄지 않고, 고른 옵션의 재고까지만 늘어남. [바로 구매]·[장바구니 담기]가 이 수량을 씀 |
| [AI로 입어보기] | 옷 입혀보기 화면의 맞는 칸(모자·상의·하의·주얼리·신발)에 넣고, AI가 연결되어 있으면 바로 입혀 봄. 연결이 없으면 안내만 함. 원피스·아우터·양말·가방·스카프는 "아직 입어 볼 수 없어요" 안내 |

- 새 파일 `view/product/OptionColors.java`: 색 이름을 실제 색으로 바꿉니다(색 낱말 약 40개).
- `Theme.outlineChip(text)`, `Theme.outlineChip(text, 채울 색)`을 추가했습니다. 기존 `Theme.chip`은 바뀌지 않았습니다.
- "수량은 장바구니에서 바꿀 수 있어요" 안내는 지웠습니다.

## 6. 홈 화면

- **카테고리 고정 줄**: 화면을 내려 "카테고리로 찾기"가 위로 사라지면, 맨 위에 카테고리 버튼 10개가 고정됩니다. 내용 위에 겹쳐 그려서 목록이 밀리지 않습니다. 고정 줄 위에서는 마우스 휠이 먹지 않습니다.
- **로고**: 홈에서 상단 "사담다"를 누르면 맨 위로 올라갑니다(`HomePanel.scrollToTop()`).

## 8. 확인하지 못한 것

- **화면 모양**: 상세 화면의 수량 줄·색상 칩, 글씨 크기 "아주 크게"일 때 화면은 실제 앱에서 아직 보지 못했습니다. 기능은 창 없이 실행해서 확인했습니다.
- **AI 입혀보기**: AI가 연결된 상태에서 자동으로 입혀지는지는 이용 열쇠가 없어 확인하지 못했습니다.
- **테스트**: `mvn test`에서 52개 중 51개가 Mockito 오류(`Could not modify all classes`)로 실행되지 않습니다. 이번 변경 전 커밋에서도 똑같이 실패하므로 환경 문제로 보입니다.
- **좁은 창**: 상품 목록의 카테고리 버튼 10개는 창 폭 1280에서는 한 줄에 들어갑니다. 더 좁으면 오른쪽 버튼이 잘릴 수 있습니다.
